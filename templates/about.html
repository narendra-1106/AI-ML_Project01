Project Objectives & Scope

The primary aim of this project is to build an interactive, data-driven web application that combines historical cricket analytics with predictive machine learning classification.

  • Predict Likely Match Winners: Classify pre-match conditions using supervised machine learning algorithms.
  • Interactive Visual Analytics: Render comprehensive historical distributions (matches per season, franchise wins, toss trends, venue stats) via Chart.js.
  • Rigorous Model Comparison: Train and compare a single Decision Tree against an ensemble Random Forest Classifier on identical chronological splits.
  • Eliminate Data Leakage: Enforce strict pre-match feature constraints and chronological validation to mirror real-world sports analytics.

Why Random Forest was chosen: Sports match prediction involves high stochastic variance. A single Decision Tree suffers from high variance and quickly overfits to specific ground-toss combinations. Random Forest aggregates 120 randomized bootstrap trees (bagging), reducing prediction variance and yielding superior F1 performance.

Key Viva Questions & Answers

Q1: Why can't we use match scores, wickets, or Player of the Match as input features?

Answer: Those are post-match variables. In a real-world predictive setting, a match winner prediction is generated before the match begins. Using post-match data would cause data leakage, artificially producing 99% accuracy on paper but rendering the model useless for upcoming games.

Q2: Why did you use a Chronological Train/Test Split instead of random train_test_split?

Answer: Sports data is temporal. If we shuffle matches randomly, the model might train on a 2024 match and test on a 2018 match, allowing future knowledge (team compositions, franchise eras) to leak into the past. A chronological split (training on ≤ 2022, testing on > 2022) tests how well the model predicts future unknown tournaments.

Q3: How does the pipeline handle unknown categories or new venues?

Answer: The Scikit-learn OneHotEncoder is configured with handle_unknown='ignore'. If an unseen venue is entered, all one-hot dummy columns for venue evaluate to 0, allowing the model to rely on team strengths and toss decisions without crashing with a ValueError.

Q4: Why are match predictions presented as probabilities rather than guarantees?

Answer: Cricket is an inherently non-deterministic sport where injuries, pitch decay, individual brilliance, and weather influence outcomes. Honest ML systems present calibrated win likelihoods (e.g., 54.8% vs 45.2%) rather than asserting guaranteed certainty.

Limitations & Future Enhancements

Current Limitations
  • Does not incorporate individual player form or dynamic squad auction changes.
  • In-match conditions (dew factor, pitch wear during 2nd innings) are not captured in match-level summaries.
  • Small sample size for newer franchises (Gujarat Titans, Lucknow Super Giants).
Future Scope
  • Integrate ball-by-ball datasets (available in archive) to compute bowler economy and batsman strike rates.
  • Implement live win-probability predictors during ongoing matches (similar to Cricinfo's Forecaster).
  • Incorporate weather and pitch report sensors using external cricket APIs.
